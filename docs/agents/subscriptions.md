# 资源订阅申请

连接器、智能体与 Skill 的可见性由各自的共享范围决定。普通用户遇到「知道有这个东西但看不到」时，可以在扩展页的「订阅」里申请订阅：部门范围的资源由所属部门管理员审批，全平台与指定人范围的资源由超级管理员审批。知识库创建权限只由超级管理员审批。

## 申请人的操作

1. 打开扩展 → 订阅 → 资源目录。目录列出连接器、智能体、Skill 的名称、描述与标识，`已可用` 表示当前共享范围已经放行。
2. 对不可用资源点「申请订阅」。待审批期间该资源显示「待审批」。
3. 在「我的申请」查看状态；已批准的订阅可以自己撤销，撤销后立即失去访问权限。被驳回的资源显示「重新申请」，提交后回到待审批。
4. 资源目录顶部还有「个人知识库创建权限」：批准后可以创建自己的知识库，知识库默认只有本人可见。

同一资源重复申请不会产生多条记录；被驳回后可以重新申请，状态回到待审批。

## 审批队列

- 扩展 → 订阅 → 待审批列出当前账号能处理的申请，含申请人、资源类型与提交时间。
- 超级管理员看到全部申请；部门管理员只看到共享范围覆盖自己部门的资源，审批其他范围返回 403「只能审批本部门范围的申请」。
- 「订阅」标签上的数字是当前账号能处理的待审批数量，管理员与超级管理员都会显示。
- 批准后申请人立刻可以在原页面看到该资源；驳回后申请人需要重新申请。
- 谁都不能审批自己的申请。
- 资源已被删除的申请会标注 `resource_missing`，可以直接驳回。

## 边界

- 订阅只补「只读访问」，不授予管理权限；审批不会修改资源自身的共享范围，因此管理员调整共享范围不会覆盖已批准的订阅。
- 私有智能体不出现在目录，也不能申请。
- 授权按资源标识（slug）保存。资源被删除后订阅记录失效；之后用同一标识重建的资源会重新沿用该记录，删除资源前请先清理相关申请。
- 目录对所有登录用户可见，但只包含名称与描述，不包含连接地址、请求头或凭据。

## API

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/subscriptions/catalog` | 登录 | 资源目录与当前用户状态 |
| GET | `/api/subscriptions/mine` | 登录 | 我的申请 |
| POST | `/api/subscriptions` | 登录 | 申请订阅 `{resource_type, resource_slug}` |
| GET | `/api/subscriptions/pending` | 管理员 | 待审批列表（按范围过滤） |
| GET | `/api/subscriptions/pending/count` | 管理员 | 待审批数量（按范围过滤） |
| POST | `/api/subscriptions/{id}/approve` | 管理员 | 批准（按范围校验） |
| POST | `/api/subscriptions/{id}/reject` | 管理员 | 驳回（按范围校验） |
| DELETE | `/api/subscriptions/{id}` | 登录 | 撤销订阅（申请人本人或超级管理员） |
| POST | `/api/knowledge/knowledge-bases` | 登录 | 建知识库（普通用户需先获批建库权限） |

`resource_type` 取 `mcp`、`agent`、`skill`。


## 资源市场

侧边导航的「资源市场」是唯一入口：按智能体、Skill、连接器分栏列出当前账号还不可用的资源，直接提交申请；「我的申请」页签可以撤回待审批或已批准的申请；管理员多一个「待审批」页签，按资源所属范围审批。扩展页不再保留订阅标签。

已经能用的资源会在资源卡片上显示「停止使用」：它只影响本人的可见性，不改共享范围，也不会影响其他用户；停止后在「资源市场」或「我的申请」点「恢复使用」即可随时恢复，不需要重新审批。停止使用过的资源不会出现在 Agent 编辑、Skill 列表和连接器列表里，恢复后立即重新出现。

申请人撤回后管理员再审批会得到 404「申请已被申请人撤回或删除」，不会把已删除记录改成已批准。申请提交后如果管理员直接调整共享范围或提升了申请人角色、使申请人已能访问该资源，目录查询会把这条件转为已批准（`decided_by=system:reconcile`），不再卡在待审批。
